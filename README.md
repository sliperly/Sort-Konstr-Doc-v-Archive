# Sort-Konstr-Doc-v-Archive

Инструменты для архива конструкторской документации (КД), организованного по номенклатуре 1С УНФ.

Конструкторы складывают архивы с документацией в сетевую папку. Структура номенклатуры в УНФ определяет, где эти архивы должны лежать. Задача проекта: читать структуру из УНФ, находить расхождения между ней и реальным архивом на диске, а затем раскладывать файлы и приводить структуру папок в порядок по коду изделия.

> **Статус: идёт переработка.** Предыдущая версия (сортировщик на основе прайс-листа, запуск через n8n) сохранена тегом [`v1-pricelist`](../../tree/v1-pricelist) и папкой `legacy/`.

## Принципы

- **Единственный ключ изделия — код `НФ-XXXXXXXX`.** Файлы без кода не переносятся, а подсвечиваются в отчётах с рекомендацией по переименованию.
- **Структура берётся из универсального отчёта УНФ** (справочник «Номенклатура») по кодам родителей. Уровни группировки Excel и прайс-лист для этого не используются.
- **Область работы:** группа «Товары», только действующая номенклатура.
- **До этапа 3 инструменты только читают.** Диск архива не изменяется.
- **Названия автоматически не исправляются, папки автоматически не объединяются.** Нормализация (латиница и кириллица, `ё/е`, регистр) нужна только для поиска и подсказок.
- **Ничего не удаляется.** Старые версии файлов будут уходить в отдельную папку с датой в имени.

## Этапы

| Этап | Что делает | Статус |
|---|---|---|
| 1 | Чтение структуры УНФ по кодам родителей, проверка названий, отчёт в Excel | готов |
| 2 | Сканирование архива на диске, подсветка расхождений со структурой, рекомендации по переименованию | в плане |
| 3 | Перенос файлов по коду, полный журнал операций, версии файлов | в плане |
| 4 | Исправление структуры папок по структуре УНФ | в плане |

## Запуск

Нужен Python 3.9+ и `openpyxl`:

```
pip install -r requirements.txt
python kd_stage1.py            # отчёт по структуре и названиям
python test_stage1.py          # автотесты
```

Входные данные: выгрузка универсального отчёта УНФ, файл `Структура.xlsx` (по умолчанию `C:\NomenklaturaSort\PriceList\Структура.xlsx`, путь можно указать ключом `--unf`).
Результат: `C:\NomenklaturaSort\reports\unf_structure_<дата_время>.xlsx`. Журнал запусков: `C:\NomenklaturaSort\logs\kd_run.log`.

## Настройка под своё окружение

Реальные пути (имя сервера, сетевые папки) в репозитории не хранятся. Скопируйте `kd_local.example.py` в `kd_local.py`, впишите свои значения. Файл `kd_local.py` исключён из git.

## Что в репозитории

| Файл | Назначение |
|---|---|
| `kd_common.py` | настройки, пороги, журнал запуска |
| `kd_unf.py` | чтение выгрузки УНФ и дерево по кодам родителей |
| `kd_names.py` | проверки названий, нормализация латиницы и кириллицы |
| `kd_stage1.py` | запуск этапа 1, отчёт в Excel |
| `test_stage1.py` | автотесты |
| `docs/` | журнал решений проекта, справка по символам в названиях |
| `legacy/` | прежняя версия сортировщика, только для истории |

## Чего в репозитории нет

Выгрузок УНФ, отчётов, журналов и локальных настроек: они исключены через `.gitignore`. Реальные данные номенклатуры в репозиторий попадать не должны.
