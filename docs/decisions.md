# Журнал решений проекта

Здесь фиксируется, что решено по проекту и в каком состоянии реализация. Дата — когда решение принято.

## Принятые решения

| № | Решение | Дата | Статус |
|---|---|---|---|
| 1 | Файлы переносятся только по коду `НФ-XXXXXXXX`. Файл без кода остаётся на месте и подсвечивается в отчётах; желательно давать рекомендацию по переименованию (самые подходящие позиции номенклатуры) | 2026-11-25 | рекомендации: этап 2, перенос: этап 3 |
| 2 | Структура берётся из универсального отчёта УНФ (справочник «Номенклатура»). Выгрузка сохраняется под именем `Структура.xlsx` | 2026-11-25 | реализовано (этап 1) |
| 3 | Иерархия строится по кодам родителей, а не по уровням группировки Excel. Причина: уровни группировки в прайс-листе противоречивы (заголовок и товары стоят на одном уровне), названия групп повторяются в разных ветках | 2026-11-25 | реализовано (этап 1) |
| 4 | Прайс-лист для формирования структуры не используется. Старый сортировщик на нём остановлен | 2026-11-26 | реализовано |
| 5 | Работаем только с группой «Товары». «Услуги» и остальные корни к архиву КД не относятся | 2026-11-25 | реализовано (этап 1) |
| 6 | Обрабатывается только действующая номенклатура. Позиции с пометкой «Недействительна» игнорируются | 2026-11-26 | **в плане**: пока эти позиции попадают в отчёт этапа 1 |
| 7 | Структуру папок скрипты пока не правят. Сначала подсветка проблем, автоисправление только после того, как подсветка проверена | 2026-11-25 | этап 4 |
| 8 | Нормализация (латиница и кириллица, `ё/е`, регистр, пробелы) используется только для поиска и подсказок. Названия автоматически не меняются, папки автоматически не объединяются | 2026-11-25 | реализовано (этап 1) |
| 9 | Наименования в УНФ исправляются в самой УНФ импортом исправленных названий. Справка по символам служит основой для инструкции сотрудникам, которые вносят изделия | 2026-11-26 | справка готова |
| 10 | Журнал операций с файлами должен быть полным и писаться по ходу работы, а не после завершения. Старые версии файлов не удаляются, а переносятся в отдельную папку с датой и временем в имени | 2026-11-25 | этап 3 |
| 11 | Режим сравнения со старым чтением прайс-листа (`--compare`) убирается: прайс-лист больше не используется | 2026-11-26 | **в плане** |

## Открытые вопросы

- Правило замены запрещённых символов в названиях (`/`, `"`, `:` и др.) при создании папок и файлов.
- Единое написание `е` или `ё` во всей базе.
- Как называть файлы, если полный путь превышает 260 символов (в выгрузке от 2026-11-25 медианный путь при полном названии изделия составлял 266 символов).
- Нужны ли папки для групп, в которых остались только недействительные изделия.

## История репозитория

- Репозиторий создан через браузер, файлы загружались вручную, связи с рабочей папкой на компьютере не было.
- Тег `v1-pricelist` — состояние репозитория до переработки (сортировщик на основе прайс-листа, запуск через n8n).
- Этап 1 переработки добавлен одним коммитом, чтобы сохранить историю разработки. Дальше этапы идут отдельными коммитами и тегами.
